# FOREXCELTECH 客户背景管理系统 MVP PRD

## 1. 文档目的

本文档定义 FOREXCELTECH 客户背景管理系统 MVP 阶段的产品范围、核心流程、页面要求和验收标准。后续开发应优先按本文档拆分任务和确认交付边界。

## 2. 产品目标

面向 FOREXCELTECH 一级代理商销售人员，提供一个 Windows 桌面端本地客户背景管理工具，帮助销售在日常拜访、聊天、电话、同事转述和项目推进过程中快速沉淀客户情报，并在下一次沟通前快速回顾客户背景、关键人关系、历史拜访记录和后续跟进事项。

MVP 的核心目标：

- 让销售可以快速创建客户、联系人和拜访记录。
- 让销售可以围绕客户查看完整背景、关键人、历史沟通和项目机会。
- 让销售可以记录后续跟进行动，并通过待办列表追踪。
- 所有数据默认保存在本地 D 盘，避免依赖网络和云服务。

## 3. 用户与使用场景

### 3.1 目标用户

| 用户 | 说明 |
|---|---|
| 一线销售 | 主要使用者，负责客户拜访、线索跟进、项目信息记录 |
| 销售主管 | 后续可能查看团队客户信息，MVP 阶段不做多人协作 |
| 代理商管理者 | 后续可能关注项目机会和客户沉淀，MVP 阶段不做独立角色 |

MVP 仅按单机单用户设计，不实现账号、权限、团队协作和云同步。

### 3.2 核心使用场景

1. 销售拜访客户前，打开客户详情，快速查看客户背景、关键人、历史沟通、项目机会和待办。
2. 销售拜访结束后，新增一条拜访记录，记录沟通主题、客户态度、关键信息和下一步动作。
3. 销售从同事处获得客户信息后，快速补充客户背景、联系人履历、关系状态和沟通偏好。
4. 销售发现新项目机会后，在客户下创建项目机会，并持续更新阶段、金额、竞争对手、风险和下一步。
5. 销售需要跟进客户时，创建待办事项，后续在工作台或待办列表中查看。
6. 销售需要迁移或整理数据时，使用 Excel 导入导出客户、联系人和拜访记录。

## 4. MVP 范围

### 4.1 必须实现

| 模块 | MVP 要求 |
|---|---|
| 工作台 | 展示近期待办、最近拜访记录、重点客户入口、基础统计 |
| 客户管理 | 客户新增、编辑、软删除、列表、详情、基础搜索 |
| 联系人/关键人 | 关联客户，维护职位、联系方式、履历、影响力、关系状态和沟通偏好 |
| 拜访/沟通记录 | 关联客户和可选项目机会，记录拜访、电话、微信、邮件、同事转述 |
| 项目机会 | 关联客户，维护阶段、金额、预计成交日期、竞争对手、风险和下一步 |
| 待办提醒 | 关联客户、联系人或项目机会，维护到期时间、优先级、完成状态 |
| 全局搜索 | 按客户名称、联系人姓名、职位、项目名称、拜访主题和摘要搜索 |
| SQLite 本地存储 | 数据库默认保存到 `D:\FOREXCELTECHClientManager\data.db` |
| Excel 导入导出 | 支持客户、联系人、拜访记录的基础导入导出 |

### 4.2 暂不实现

- 云同步。
- 多用户账号和权限。
- 团队协作、审批和分配。
- 移动端。
- 多语言。
- 复杂动画和营销型首页。
- 自动从邮件、微信或 CRM 抓取数据。
- 高级 BI 报表。
- 数据加密和权限控制，留到云同步或多人使用前设计。

## 6. 页面与功能要求

### 6.1 工作台

目标：打开软件后第一屏直接进入可用工作台。

必须展示：

- 今日和逾期待办。
- 最近 7 天拜访/沟通记录。
- 重点客户数量。
- 进行中的项目机会数量。
- 快捷操作：新增客户、新增联系人、新增拜访记录、新增待办。

验收标准：

- 用户打开应用后无需进入营销页或欢迎页。
- 可以从工作台进入客户详情、拜访记录详情和待办详情。
- 没有数据时显示空状态，并提供新增入口。

### 6.2 客户列表

目标：销售可以快速找到客户并进入详情。

列表字段：

- 客户名称
- 行业
- 区域
- 状态
- 重要等级
- 负责人
- 最近沟通时间
- 未完成待办数

筛选与排序：

- 按客户名称搜索。
- 按状态筛选：潜在、活跃、停用。
- 按重要等级筛选。
- 默认按更新时间倒序。

验收标准：

- 支持新增客户。
- 支持编辑客户基础信息。
- 支持软删除客户。
- 删除前必须二次确认。
- 已软删除客户默认不出现在列表中。

### 6.3 客户详情

目标：围绕一个客户聚合完整背景。

必须展示：

- 客户基础信息。
- 客户背景和备注。
- 关键联系人列表。
- 拜访/沟通时间线。
- 项目机会列表。
- 未完成待办。
- 附件列表，MVP 可先只展示元数据入口。

验收标准：

- 可以从客户详情新增联系人、拜访记录、项目机会和待办。
- 新增内容自动关联当前客户。
- 时间线按发生时间倒序。
- 页面信息密度高，避免大面积装饰性内容。

- 职位

- 决策角色

### 6.10 工作台日历（规划）

目标：让销售在工作台直接看到客户拜访节奏，区分“已经拜访”和“计划但尚未拜访”的日期，降低漏跟进风险。

核心原则：

- 日历是销售每日进入系统后的第一视图之一，应优先服务“今天要做什么、哪些客户已沟通过、哪些计划未完成”。
- 日历不替代拜访记录，日历上的已拜访状态来自正式拜访记录，计划状态来自计划拜访数据。
- 计划拜访必须允许人工维护，不能依赖 AI 自动生成。
- 已拜访和计划未拜访需要使用清晰但克制的颜色区分，避免界面过于花哨。

MVP 功能范围：

- 工作台展示月视图日历。
- 某天存在已完成拜访记录时，日期标记为“已拜访”颜色，默认建议绿色系。
- 某天存在计划拜访但尚未完成时，日期标记为“计划未完成”颜色，默认建议红色或粉色系。
- 同一天同时存在已拜访和计划未完成时，优先显示“计划未完成”颜色，避免未完成计划被已拜访状态掩盖；详情弹框中分开展示两类记录。
- 某天关联多个客户时，在日期右上角显示数量角标。
- 数量角标最大显示值可配置，默认最大值为 99，超过后显示 `99+`。
- 点击某一天打开日历详情弹框。
- 日历详情弹框中展示该日已拜访客户、计划拜访客户。
- 支持在日历详情弹框中新增、编辑、取消计划拜访。
- 支持将计划拜访关联到实际拜访记录，完成后状态从“计划未完成”变为“已完成”。
- 设置页支持配置日历标准马卡龙配色，包括已拜访和计划未完成颜色。

验收标准：

- 工作台日历不重复展示今日大标题；回到今天使用低调图标按钮；年份和月份拆分为小型选择按钮；鼠标在日历区域滚动可切换月份。
- 有正式拜访记录的日期能正确标记为已拜访。
- 有计划但未完成拜访的日期能正确标记为计划未完成。
- 点击日期可以查看和维护当天拜访安排。
- 从日历新增计划拜访后，刷新或重启应用仍保留数据。
- 过去日期不能新增或保存计划拜访，只能补录正式拜访记录。
- 标记计划拜访完成时，必须关联或创建一条正式拜访记录。
- 颜色和数量上限配置保存到 D 盘配置文件。

### 6.11 客户地图（规划）

目标：用地图帮助销售从区域角度理解客户分布、拜访覆盖和重点区域，第一版只做到中国地图、省份和城市级标注。

核心原则：

- 第一版不做街道级精确定位，不接入在线地图 API，不上传客户地址。
- 地图数据应本地优先，优先使用开源中国地图 GeoJSON 或同类静态地图数据，减少重复开发量。
- 客户地图是区域分析和跳转入口，不替代客户列表。
- 新建或编辑客户时，应尽量补齐省份、城市等结构化地址字段，地图只使用结构化省市信息。

MVP 功能范围：

- 左侧导航新增“客户地图”入口。
- 客户地图首页展示中国地图，页面标题使用“客户分布”。
- 中国地图按省份展示客户数量或客户状态分布。
- 支持按客户状态、行业筛选地图展示。
- 点击某一省份后进入省份视图。
- 省份视图以城市级别展示客户标记点。
- 省份视图侧边展示该省全部客户列表，支持上下滚动。
- 点击城市标记点时，展示该城市客户摘要。
- 点击侧边客户列表项或客户摘要时，打开对应客户详情弹框或跳转到客户详情。
- 新建客户或编辑客户省市信息后，客户地图自动刷新。
- 缺少省份或城市字段的客户进入“待补充定位信息”列表，不强行展示在地图上。

数据要求：

- 客户需要逐步补充结构化地址字段：省份、城市、详细地址；区县不在界面单独展示，可填写在详细地址中。
- 第一版地图标注精度到城市，不要求经纬度。
- 如果未来需要更高精度，再单独评估本地地理编码或离线地址库。

验收标准：

- 客户地图可以离线打开，不依赖外部地图服务。
- 中国地图能展示各省客户分布。
- 点击省份可以进入省份客户视图。
- 省份视图可以展示城市级客户点位和客户列表。
- 客户状态、行业筛选能影响地图和侧边客户列表。
- 新建客户填写省市后，地图中对应省市能看到该客户。
- 缺少省市的客户不会造成地图异常，并能在待补充列表中找到。

## 8. 非功能要求

### 8.1 平台

- Windows 10/11 x64。
- Electron + SQLite。
- 本地优先，不依赖网络。

### 8.2 性能

- 1 万条客户以内，列表和搜索应保持可接受响应。
- 常见列表查询应在 1 秒内返回。
- 应避免一次性加载所有详情数据到单个页面。

### 8.3 可用性

- 第一屏直接进入工作台。
- 主要操作不超过 2 次点击进入表单。
- 表单必填项清晰标记。
- 保存失败需要展示明确错误原因。
- 删除、覆盖导入等危险操作需要二次确认。

### 8.4 数据安全

- MVP 阶段不做云同步。
- MVP 阶段不做用户权限。
- 数据保存在本地 D 盘应用目录。
- 后续云同步前必须补充加密、备份恢复和权限设计。

## 10. MVP 验收标准

MVP 可交付时必须满足：

- 应用可在 Windows 上启动。
- 数据库自动创建在 `D:\FOREXCELTECHClientManager\data.db`。
- 用户可以新增、编辑、查看和软删除客户。
- 用户可以为客户新增、编辑、查看和软删除联系人。
- 用户可以为客户新增、编辑、查看和软删除拜访记录。
- 用户可以创建项目机会和待办。
- 工作台可以展示基础统计、近期拜访和未完成待办。
- 顶部搜索可以检索客户、联系人、项目和拜访记录。
- Excel 导出可用。
- Excel 导入至少支持客户、联系人和拜访记录。
- 所有项目运行数据默认落在 D 盘明确目录。

## 11. 待确认问题

- 客户状态是否固定为潜在、活跃、停用，还是允许自定义。
- 关系状态是否需要固定枚举，例如陌生、已认识、熟悉、信任、风险。
- 项目机会阶段是否采用固定枚举，是否需要允许用户自定义。
- Excel 导入是否要求兼容现有客户数据模板。
- 附件在 MVP 中是否只保留元数据，还是需要完成真实文件复制和打开。
- 是否需要提供一键备份数据库功能作为 MVP 的一部分。
