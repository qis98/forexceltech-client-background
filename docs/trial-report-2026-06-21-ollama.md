## 1. 测试目标

验证当前 MVP 在本地 Ollama `qwen3:8b` 环境下，能否完成以下真实用户路径：

1. 在设置页确认 Ollama 连接可用。
2. 在智能录入页粘贴一段销售拜访文字稿。
3. 生成客户、联系人、拜访记录三类草稿。
4. 人工确认后写入正式数据库。
5. 在客户、联系人、拜访记录全局页面检索到写入数据。

## 4. 发现问题

1. 客户名称被截短。
   - 原文客户名是 `Ollama模拟测试-20260621-宁波封测`。
   - 模型抽取结果为 `宁波封测`。
   - 风险：真实客户全称可能被模型简化，导致客户重复或无法按正式名称管理。

2. 首轮多联系人支持不足。
   - 原文包含 `赵经理` 和 `孙工`。
   - 当前只生成 1 张联系人草稿：`赵经理`。
   - 风险：一次拜访里多个关键人无法一次性沉淀。
   - 后续处理：已在第 11 项扩样评估后改造为多联系人草稿，详见本文第 7 节。

3. 拜访主题过泛。
   - 模型生成主题为 `Ollama模拟测试`。
   - 更合理主题应接近 `宁波封测新产线设备选型沟通`。
   - 风险：拜访记录列表可读性不足。

4. 摘要存在轻微文字错误。
   - 摘要中出现 `孙、工`。
   - 风险：模型输出需要人工校对，当前界面应更突出“模型结果需复核”。

5. 人工修正体验仍需加强。
   - 虽然页面允许编辑草稿字段，但长草稿中关键字段分散。
   - 建议后续把客户名称、联系人姓名、拜访主题、下一步动作这类高风险字段做成更醒目的确认区。

## 5. 产品判断

当前 Ollama 本地智能录入 MVP 已经能跑通业务闭环：

```text
文字稿 -> Ollama 抽取 -> 草稿 -> 人工确认 -> 客户/联系人/拜访记录入库 -> 全局检索
```

但距离可交给真实销售长期使用，还需要继续做小样本准确率评估。重点不是“能不能生成”，而是：

- 正式客户名称是否完整。
- 多联系人是否完整。
- 拜访主题是否可读。
- 摘要是否忠实原文。
- 下一步动作是否准确。

## 6. 首轮建议下一步

首轮试用后的建议是继续执行 PRD 第 11 项，把评估样本拆成 10-20 段，并记录每段的字段准确率。该建议已在本文第 7 节落实。

优先优化方向：

1. Prompt 中明确“客户名称必须尽量保留原文完整称呼，不要自行截短”。
2. 数据结构支持多个联系人草稿。
3. 拜访主题生成规则改为“客户简称 + 核心事项”。
4. 在确认写入前增加关键字段复核区。

## 7. 第 11 项扩样评估和实现结果

### 7.1 扩样评估范围

已使用 12 段模拟脱敏销售文字稿进行本地 `qwen3:8b` 结构化抽取评估，覆盖：

- 单客户多联系人。
- 客户名称较完整和客户名称缺失。
- 采购、设备、工艺、负责人等多角色参会。
- 下一步动作明确的销售跟进文本。
- 口语化拜访记录和较短文本。

```text
scripts/evaluate-ollama-extraction.js
```

改造前系统只支持 1 张联系人草稿。

|---|---:|
| 样本数 | 12 |

结论：模型可以稳定输出 JSON，也能较好提取下一步动作，但单联系人数据结构限制了真实拜访场景。

### 7.3 改造内容

已完成以下改造：

- 智能录入数据结构从单个 `contact` 改为 `contacts` 数组。
- Ollama JSON Schema 要求输出多个联系人。
- Prompt 明确要求保留谈话中出现的每位关键联系人。
- 前端显示“联系人草稿 1”“联系人草稿 2”等多张联系人草稿。
- 每张联系人草稿支持单独确认写入。
- “全部确认写入”按客户、所有联系人、拜访记录顺序入库。
- 拜访记录自动关联本次确认的多个联系人。
- 仍兼容旧格式 `contact`，避免旧草稿无法读取。

### 7.4 改造后结果

| 指标 | 结果 |
|---|---:|
| 样本数 | 12 |
| Ollama 输出成功 | 12/12 |
| 客户名称准确 | 8/12 |
| 多联系人完整识别 | 11/12 |
| 下一步动作命中 | 12/12 |
| 平均耗时 | 约 35.6 秒 |

结论：多联系人草稿是有效改造，联系人完整性从 0/12 提升到 11/12。耗时增加可以接受，但后续需要观察真实电脑上的使用体验。

- 同一段文字稿可生成“联系人草稿 1”和“联系人草稿 2”。
- 全局“全部确认写入”可写入客户、多个联系人和拜访记录。
- 写入后的拜访记录可显示多个参与联系人。

验证脚本：


### 7.6 剩余问题

客户名称和客户匹配仍是当前最大风险：

- 12 段样本中客户名称准确率为 8/12。
- 模型会把正式客户名称截短为简称。
- 模型可能误匹配已有客户。
- 当文字稿没有明确客户信息时，模型无法可靠判断客户。

产品判断：

- 人工预关联客户/联系人仍应作为优先路径。
- 客户名称、匹配客户和匹配原因应成为下一步重点复核区。
- 不能静默用模糊匹配自动合并客户，高风险匹配必须人工确认。
