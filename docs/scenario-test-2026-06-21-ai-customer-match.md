# 智能录入客户匹配确认场景测试

日期：2026-06-21

## 1. 测试目标

验证智能录入在客户名称可能被截短、且系统发现疑似已有客户时，不会静默复用候选客户，必须由用户人工确认。

## 2. 测试场景

输入文字稿：

```text
6月20日到上海精密制造拜访，地点在客户二楼会议室。张总负责拍板，周主任负责技术评估。客户准备升级检测设备，重点关注稳定性、售后和付款条件。下一步约下周三线上技术评审。
```

已有客户中存在：

```text
AI录入测试客户-20260620-上海精密
```

该场景代表真实使用中的风险：模型或规则可能把“上海精密制造”和已有“上海精密”识别为同一客户，但它们也可能是不同客户。

## 3. 测试结果

智能录入生成草稿后，页面出现“客户匹配确认”区域。

候选客户显示：

```text
AI录入测试客户-20260620-上海精密 · 82分 · 抽取名称与客户全称部分重合、行业一致、区域一致
```

未选择“使用已有客户”或“按草稿新建客户”时，点击“全部确认写入”，页面提示：

```text
请先在“客户匹配确认”中选择使用已有客户或按草稿新建客户。
```

结论：通过。系统没有静默把草稿合并到候选客户。

## 4. 产品判断

当前策略符合“人工预关联优先，AI 判断只做辅助”的产品原则：

- 用户预关联客户时，直接使用预关联客户。
- 未预关联但存在候选客户时，必须人工确认。
- 用户可以选择使用已有客户，也可以修改客户草稿名称后新建客户。
- 模糊匹配结果只作为候选提示，不作为自动合并依据。

## 5. 剩余观察点

- 候选评分目前是 MVP 规则，后续可根据真实样本调整阈值。
- 客户名称被模型截短的问题仍需要靠草稿复核和人工编辑兜底。
- 真实销售试用时应重点记录“候选客户太多”或“候选客户漏掉”的情况。
